# 이력서·면접 주장 범위

## 바로 사용할 수 있는 요약

> 2022~2025년 Rust 기반 시장 데이터 시스템을 개인 프로젝트로 설계·구현하며 수집·배치·PostgreSQL 집계·Actix API·Yew/WASM 웹 계층을 다뤘습니다. Spring Batch의 Batch/Job/Step 모델을 참고한 실행 구조도 직접 만들었습니다. 2026-10 공개 준비 과정의 AI 보조 감사에서 실패 종료 처리와 ISO 주차 경계 문제를 확인했고, 원본과 분리한 합성 예제·회귀 테스트로 수정안을 검증했습니다.

## 이력서용 핵심 bullet

- 2022~2025년 Rust 기반 시장 데이터 수집·집계 시스템을 개인 프로젝트로 설계·구현하고, Go 프로토타입 및 별도 Spring 기반 구현까지 기술 선택을 실제 코드로 비교
- Rust로 `Batch → Job → Step` 실행 모델을 설계하고 장기간 확장한 경험을 보유; 2026-10 AI 보조 공개 감사에서 반환 오류의 종료 상태 누락을 확인하고 독립 재구성 예제로 검증
- PostgreSQL 일별 데이터를 주간 단위로 집계하고 transaction-scoped advisory lock을 적용; append-only 전제의 공개 합성 테스트에서는 ISO 연도/주차 경계와 변경 없는 upsert의 멱등성을 검증
- Actix Web·SQLx API와 Yew/WASM 프런트를 구성하고, 보관된 역사적 UI의 release WASM 빌드를 재현
- Rust crate `tb_row` 배포 및 Actix 공식 examples 저장소에 multipart·object-storage 예제 기여

## 면접에서 덧붙일 설명

“처음부터 완벽한 프레임워크를 만든 것은 아닙니다. 공개 준비 과정에서 AI 에이전트와 함께 원본을 감사하니 실패 시 종료 기록 누락과 연도 경계 집계 문제가 보였습니다. 원본을 완벽하다고 주장하는 대신, 공개 가능한 작은 코드와 합성 데이터로 수정안을 재구성해 테스트했습니다.”

이 설명은 약점을 자백하는 데서 끝나지 않고, 설계 의도·실패 의미·수정·검증까지 보여줍니다.

## 포트폴리오에서 제외한 링크

기존 Go 저장소와 초기 인프라 저장소는 현재 포트폴리오 공개 기준에 맞게 정리되지 않아 링크하지 않습니다. 기존 Gist도 코드 품질과 설명 범위가 이 사례집보다 약해 대표 링크로 사용하지 않습니다. Stack Overflow 프로필은 이번 사례집의 핵심 근거로 사용하지 않습니다.
